# hc-bridge app 内置 MCP 鉴权 / OAuth / 管理页 / Tunnel 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) for tracking.

**Goal:** 给 app 内的 `McpService`（`127.0.0.1:8765`，现无鉴权）加内嵌 OAuth 2.1 AS/RS、静态 key、三层工具策略与时间窗、app 内管理页、Cloudflare Tunnel 配置与状态；默认要求鉴权。

**Architecture:** 纯 Kotlin 协议核心（`id.harness.hcbridge.auth`，无 Android 依赖 ⇒ JVM 单测）+ 平台 `SQLiteOpenHelper`（WAL，进程内单例）存储，`McpService` 只做 socket/HTTP 拆包并把路由结果交给 JSON-RPC 分发；同意与管理都在 app UI 内，HTTP 侧没有任何管理路由。

**Tech Stack:** Kotlin 2.0.21、Android Gradle Plugin 8.9.3、`android.database.sqlite`、`java.security`/`javax.crypto`（SHA-256、PBKDF2、HMAC-SHA1）、`org.json`、Material 3 + XML 视图（现有风格，**不引入 Compose**）、`EncryptedSharedPreferences`（已在 `Secure.kt`）。

**Spec:** `docs/superpowers/specs/2026-11-02-app-mcp-design.md`（执行者必须同时读；NAS 协议细节对照 `docs/superpowers/specs/2026-11-02-oauth-admin-design.md` §6）

## Global Constraints

- 只监听 `127.0.0.1:8765`；**永不** bind `0.0.0.0`；公网只经 Termux 里的 `cloudflared` 转发。
- `requireAuth` 默认 `true`；`allowLoopbackNoAuth` 默认 `false`（必须管理员显式开启）。
- 鉴权优先级（fail closed）：**免鉴权只在** `requireAuth=false` **且** `allowLoopbackNoAuth=true` **且** `publicBase==null` **且** `tunnelMode=="off"` **且** 对端是回环 **且** 请求不带任何转发头时成立；其余一律要 Bearer。`requireAuth=false` 单独不构成豁免。
- 访问令牌 TTL 1 小时，刷新令牌 30 天，授权码 5 分钟且一次性；刷新严格轮换，重用吊销整个 family。
- scope 只有 `health.read` / `health.write`；`ingest` 是保留 scope，**永不**经 `/authorize` 或 `/token` 发放（请求它 → `invalid_scope`）。
- 工具总数 **36**（`health.read` 20 个 + `health.write` 16 个）；目录必须与 `McpTools.json()` 完全一致。
- 令牌、授权码、client secret、静态 key 只存 SHA-256；比较用 `MessageDigest.isEqual`。不引入 JWT/JWKS/introspection。
- 限流：`/register` 10/h、`/token` 60/min、`/authorize` 30/min（`?req=<id>` 的状态刷新不计入）。
- 公网 issuer 必须 `https`；非 https 的 `redirect_uri` 一律拒绝，`http://127.0.0.1`、`http://localhost`、`http://[::1]` 例外。
- 管理面只在 app UI 内：HTTP 上**没有** `/admin*` 路由。
- 请求体上限 256 KB，超限在读入前拒绝（`413`）。
- 不新增第三方依赖（Room/Compose/biometric 都不加）；`EncryptedSharedPreferences` 只经 `Secure` 使用，TOTP secret 也放那里。
- 不改 `deploy/nas/`；不改 `SyncWorker`/`HcPusher`/`CmdReceiver`/Health Connect 读写与同步行为。
- app 健康数据仍单用户单库（Health Connect）；任何令牌/策略只作用于 MCP 请求，不作用于同步。
- 日志与审计不得出现 token、code、client secret、静态 key、Cookie、健康数据、工具参数值。
- 测试：`./gradlew :app:testDebugUnitTest`、`./gradlew :app:lintDebug`、`ANDROID_SERIAL=emulator-5554 ./gradlew :app:connectedDebugAndroidTest`。
- 构建/装机在 `win` 上做，装到 `phone`；本计划不涉及 NAS。

## 设计决定（实现者不要另选）

1. **存储**：平台 `SQLiteOpenHelper`（`mcp.db` v1，`enableWriteAheadLogging()`）。仓库里没有 Room，Room 是新依赖 ⇒ 不用。**全进程只有一个 store**：`object Store { fun of(c: Context): McpStore; fun overrideForTest(s: McpStore? = null) }`，Activity/Service 都走 `Store.of(...)`，避免两个 helper 各开一条连接；androidTest 用 `Store.overrideForTest(SqlMcpStore(McpDb(ctx, "test-<uuid>.db")))` 注入临时库。JVM 单测用 `InMemoryStore`。
2. **同意流**（无浏览器登录、无 Cookie 会话）：`GET /authorize` 校验后写 `oauth_pending`（id 不可猜），返回静态 HTML「请在 app 内确认」，页内**有明确链接** `<a href="hcbridge://oauth/consent?req=<id>">在 app 内确认</a>`；同屏给出跨设备说明（PC 浏览器无法打开手机 app 时，改用手机浏览器、或用 app 内「待确认请求」列表直接批准/拒绝，见决定 3）。决策写回 `oauth_pending` 后，浏览器刷新即 `302` 到 `redirect_uri`。因此 spec §6 的 `sessions` 表**不实现**；没有网页表单 ⇒ 没有 CSRF 面，防篡改靠服务端暂存请求（spec §9 的「服务端暂存」分支）。
3. **待确认请求不靠浏览器**：app 内管理页有「待确认请求」段（客户端名、回调主机、scope、有效工具数、发起时间、允许/拒绝），tunnel/跨设备场景不依赖浏览器跳转。批准仍要过 `AdminGate`。
4. **pending 幂等**：同一 `client_id + code_challenge + redirect_uri + resource + scopes` 仍有未过期 `pending` 行 ⇒ 复用该行，`303 See Other` 到 `/authorize?req=<id>`；刷新间隔 ≥ 3 秒；`?req=` 的状态查询不占限流额度；每次进入 `authorize`/状态路由顺带清理过期 pending。
5. **层数**：app 没有 `users` 表 ⇒ 三层策略（客户端 / 令牌 / 静态 key）取交集；管理员本人不经 MCP，不受时间窗限制。`Principal` 携带**全部**策略/时间窗层（OAuth = 客户端层 + 令牌层；静态 key = key 层）。
6. **管理员身份**：PBKDF2 密码（`pbkdf2$sha256$<iter>$<salt>$<hash>`）；设备有锁屏时优先 `KeyguardManager.createConfirmDeviceCredentialIntent` 快捷解锁。两者都经同一个 `AdminGate`。
7. **TOTP**：自写 HMAC-SHA1/30s/6 位（无新依赖），RFC 6238 向量单测；secret 只经 `TotpSecret`（持有 `Context`，内部走 `Secure`，键 `totpSecret`）读写，**不进** `McpConfig`（`McpConfig` 不碰 `Secure`）、不进 settings 表、不进日志。恢复码不做 —— 恢复路径就是这台设备本身。
8. **Tunnel**：app 只存配置、拼命令、探测公网可达；不启动/不杀 `cloudflared`（Termux:API 的 `RUN_COMMAND` 不实现）。`publicBase != null` **或** `tunnelMode != "off"` ⇒ 强制 `requireAuth=true`，且**关闭空闲自动停**（公网要一直在）。
9. **DCR 防钓鱼**：默认 `confirmNewClients=true`，动态注册的客户端落库为 `status='pending'`，管理页出现「待批准客户端」；未批准客户端走 `/authorize` 返回 `403` HTML。同意页固定显示警告文案（「只有你自己发起连接时才允许；不要把验证码/授权页发给别人」）。
10. **审计链基**：prune 最旧行时把被删最后一行的 `hash` 写进 `settings("auditBaseHash")`；`auditChainOk()` 从该基开始校验，删旧行不会让链校验失败。

## Review Focus

1. **回环豁免被 tunnel 借用**：豁免要同时满足 `requireAuth=false`、`allowLoopbackNoAuth=true`、`publicBase==null`、`tunnelMode=="off"`、回环对端、无转发头（`CF-Connecting-IP`/`X-Forwarded-For`/`CF-Ray`/`X-Real-IP`/`Forwarded`/`True-Client-IP`）；少任一条都必须 401。
2. **刷新令牌重用**：旧刷新令牌再换一次必须 `invalid_grant` 并吊销整个 family；实现是「先 `tokenByHash` 判重用 ⇒ 不满足才走单条 CAS `consumeRefresh`」，不允许把 CAS 结果当授权依据、也不允许两步写同一行。
3. **公网基址切换**：改公网地址后旧 `resource` 的访问令牌必须 401（客户端重新授权）。
4. **客户端被吊销/损坏**：任何一次 `/mcp` 校验都要重读 client；缺失、已吊销或 JSON 损坏 ⇒ 立刻吊销该令牌 family 并 401（fail closed），不能只看令牌行。
5. **策略/时间窗损坏与空集**：`[]` = 一个工具都不许（不是"不限制"）；非法 JSON 不得退化成"放行"，要 `policy_corrupt`/`window_corrupt` 拒绝；跨午夜时段与 `until` 含当天。

- [ ] **Step 3: 实现 `OAuth`**

要点：`validateAuthorize` 要求 `response_type=code`、`code_challenge_method=S256`、client 存在、未吊销、`status=="active"`（pending → `OAuthError("unauthorized_client", status = 403)`）、`redirect_uri` 与注册值精确相等；`scope` 缺省 = 两个 scope，超出或含 `ingest` → `invalid_scope`；`resource` 缺省 = `ep.resource`，给出时必须相等。`createOrReusePending` 先 `findPending`，命中返回 `(id, false)`，否则插入 `TokenFormat.REQUEST_PREFIX + Crypto.randomToken(24)` 并返回 `(id, true)`。pending 是**一个**状态机：`pending →(decidePending CAS) approved|denied →(consumePending CAS) consumed`；`decidePending` 只从 `pending` 出发，批准时把授予的 scope 写进该行（`scopes_json` 覆盖为交集）；`completePending` 只从 `approved` 出发，`consumePending` 成功后才 `putCode`，失败一律 `OAuthError("access_denied", status = 410)`。`exchange` 校验 client/redirect/`resource`/PKCE，写 access（`hcb_at_`，1h）与 refresh（`hcb_rt_`，30d，新 `familyId`）。`refresh`：**先 `store.tokenByHash(hash)` 读**——行存在且 `replacedByHash != null` 或 `revokedAt != null` ⇒ `revokeFamily(familyId)` + `invalid_grant`（重用即全族作废，审核点 2）；否则再 `store.consumeRefresh(hash, now)` 单条 CAS，取不到（并发被抢）同样 `invalid_grant`；成功则插新 refresh（同 family，`putToken` 一次写全，含 `replacedByHash` 回填），不二次 UPDATE。`revoke`：`client_id` 与令牌归属不匹配 ⇒ 直接返回（200，不动）。`registerClient`：限 200 个；`redirect_uris` 逐条校验（`https`，或 `http://127.0.0.1`、`http://localhost`、`http://[::1]`，不得含 fragment）；`confirmNewClients=true` ⇒ `status="pending"`。

`GET /authorize?req=<id>`（状态页，**三个分支都要实现**）：`status=='pending'` 且未过期 → `200` 等待页（同样的 `hcbridge://` 链接 + `refresh 3`）；`approved` → `completePending` → `302` 到 `redirect_uri`（`code`+`state`）；`denied` → `302` 到 `redirect_uri`（`error=access_denied`）；不存在/已 `consumed`/过期 → `410 Gone`（HTML，「请回到客户端重新发起」）。每次进入先 `deleteExpiredPending(now)`。**限流只豁免上面那个 `200` 分支**：`302`/`410` 照常计入 `/authorize` 额度。
受保护：`POST /mcp`（含 `/mcp/...` 前缀）。`GET /mcp` → 405。
校验失败一律 `400` + HTML + `Cache-Control: no-store`，**不**重定向；`pending` 客户端 → `403`。

- [ ] **Step 4: 实现鉴权门、body 上限与限流**

`trustedLoopback(req, config)` = `!config.requireAuth && config.allowLoopbackNoAuth && config.publicBase == null && config.tunnelMode == "off" && req.peerLoopback && 无转发头`（六条全满足才豁免；`allowLoopbackNoAuth` 是唯一的显式开关，`requireAuth=false` 单独不构成豁免）。`/mcp`：`declaredTooLarge(content-length)` → `413`；否则先 `trustedLoopback` 豁免（命中则 `Route.Mcp(Principal("loopback","local","本机", setOf(SCOPE_READ, SCOPE_WRITE), emptyList(), emptyList(), ToolCatalog.ALL_TOOLS, Long.MAX_VALUE), body)`），再 `Authorization: Bearer` → `Principals.resolve`；失败 `401` + `WWW-Authenticate`。限流键：只有 `config.tunnelMode != "off" && config.publicBase != null`（确实在走 tunnel）时才用 `"cf:" + cf-connecting-ip`；其余情况（含 tunnel 关闭时仍带该头）一律用固定键 `"local"`，本地客户端无法靠伪造头换桶。

- [ ] **Step 3: 改 `McpService` 的读体与响应**

读头**在字节层**：`BodyReader.readHead(input)` 读到 `\r\n\r\n` 为止（ISO-8859-1 解码），再解析请求行与头（键小写）；在读之前先把 socket 的 `InputStream` 套一层 `BufferedInputStream`（`readHead` 是逐字节读的，裸 socket 等于一次一 syscall）；**不要**用 `BufferedReader`（它会预读、把 body 字节吃掉）。`readHead` 返回 `null`（超 16 KB）→ `413`。读体继续用**同一个** `InputStream`：`val declared = contentLength`；`BodyReader.declaredTooLarge(declared)` → 直接 `413` 且**不读 body**；否则 `BodyReader.read(input, declared)`（读到 CAP 就停，`null` → `413`）。响应统一走 Task 5 的 `respond(os, resp: HttpResp)`（状态短语表在 `HttpStatus.reason`；它自己算 `Content-Length`/`Connection: close`，`McpService` **不要**再拼一遍）。
